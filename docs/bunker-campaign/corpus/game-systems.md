## 2. Recall and teleport

**Stock.** There is no recall item. Travel between levels is a gate calling `IPRGameMode::TransferToLevel(LevelTag, LocationTag)`.
- `Misc/BP_ZoneGate` (box trigger `Trigger_Width` 200, `ExitPoint`, `LevelTo`, `LevelFrom` set from `GetActorLevelTag` in the construction script, `PairedGateTag`, `Activated`) [data]. `Misc/BP_ZoneGate_Shortcut` adds `ActivationTrigger` (a `PRGameData` trigger tag) and `HintText`. `BP_ZoneGate_ShootingRange`, `BP_Tutorial_ZoneGate` also exist. Hub placement: `L_Hub_MapPoints` has 1 `BP_ZoneGate`, 2 `BP_ZoneGate_Shortcut`, 1 `_ShootingRange` [data].
- `Misc/BP_ConditionalTransfer` (parent `PRBasicActorWithConditions`): `LevelTag`, `LocationTag`, `DelaySeconds` 5; fires `TransferToLevel` when its conditions (player level, item, mission state, trigger passed) hold [data]. This is a stock "transfer on condition" actor.
- Gates also appear as `DA_MapPointsConfig.LevelGates` rows (`LeadsFrom`, `LeadsTo`, `UnlockTrigger`, `LocationInLevel`) which the tablet draws [doc ingame-map.md 1].
- Arrival: `BP_PRGameMode.FindLevelStart` = saved position for that level, else the `BP_ZoneGate` whose `LevelFrom == Level` and `PairedGateTag == Location`, else the first `PlayerStart` in the level [doc native-loading-tides.md 1.1 step 4].
- Fog teleport: `BP_TideBase.DoTransition` = `SavePosition(CurrentLevelTag, pos)` + `ReEnterCurrentLevel()` [doc native-loading-tides.md 2.1, 2.3].

**Showcase today** [code unless stated]:
- Entry to the map: pick up the Hub tin `Liquid08_1` (`config.lua:61`), F9, or console `itrshowcase enter`. The loader calls `TransferToLevel(Level.Zone.ItrShowcase, None)` through the interface function (`main.lua:1488`).
- Exit ("recall") = stand-on trigger: seven return pads R0-R6. Each is a cylinder pad + beam mesh (`marker:return` material) plus `TargetPoint`s tagged `itr:exit` + `itr:exit_id:R<n>` and `itr:arrive:R<n>` (`gen/tools/v4/placements.py:34-51`). It remembers the exit id; the next entry arrives at the matching `itr:arrive:<id>` (`ReEntry = true`). Pad positions (map-local m): R0 (-1095,-215), R1 (-990,640), R2 (650,-650), R3 (740,1060), R4 (1165,120), R5 (195,70), R6 (-60,-670) [brief.json returns]. - Starting spawn: `PlayerStart` plus `TargetPoint` tag `itr:player_start`, 2 m east of pad R0 (Kordon entrance), `NativeStart` (-143800,-385500,3184) [code]. Also a perimeter `PlayerStart` (`build_showcase.py:2126`).

## 3. Tide, respawn and rifts

Start: `docs/itr-showcase/research/native-loading-tides.md` (sections 2-3) and `sdk-gameplay-bps.md` section 3. Facts used:

- **Period.** `UGameConfig.TidePeriodInGameHours` = 100 game hours; 1 game hour = 2.5 real min (`RealMinutesInGameHour`), about 4 h 10 min real time at default speed, scaled per difficulty by `GameDifficultyConfig.TideTime` [doc native-loading-tides.md 3; sdk :2876, :3375]. `PRGameData.GetGameSecondsToTide / GetRealSecondsToTide / GetSecondsLastTide` exist [sdk :7888-7923]. Cheat `PRCheatManager.ResetTideTimer` and `WBP_Cheats` tide button force one [sdk :6593].
- **Sequence** (bytecode [doc]): native `OnTideHappening(bReload)` -> `BP_PRGameMode.OnTideHappening` -> `GetCurrentLevelTide` (the `BP_TideBase` whose `Environment.EnvironmentLevelTag == CurrentLevelTag`) -> random `PlayerSpawn` spline point, `SavePosition`, `AnimateTide` -> `OnTideFinished`: **if the player overlaps a `BP_ShelterVolume` the current transform is saved instead of the random respawn**; then `PRGameData.ApplyTideReset()`; if `bReload` then `ReEnterCurrentLevel()`; `KillActorsOnReload` removes spawned NPCs, generators, spawners, anomalies, stashes, corpses first. The tide also re-rolls missions (`GenerateNewMissions(bTide)`, `RestrictMaxSuccessfulPerTide`) [doc missions.md 1.2].
- **Shelters in stock.** `BP_ShelterVolume` (a `TriggerBox`, no logic of its own) is placed in every zone's persistent level: Buffer 3, Castle 2, Construct 2, Factory 2, Kolhoz 4 [data: `dump` counts]. Stock "player shelter" prefabs `Prefab_Zone_Buffer_Shelter_01_a` and `Prefab_Zone_Construct_Shelter_01_a` are NOT underground: their meshes are water-tower cistern / ladder / wooden platforms (Buffer at z 1500, on a tower) and fallen-pylon wooden floors [data: component lists in `build/work/T-155/bp/Prefab_Zone_*_Shelter_01_a.json`]. The catalogue's "bunk, door" guess (`asset-catalogue.md:728`) is wrong on this.
- **Which levels reload.** Per-level `ReloadOnTideHappening`: zones true, Hub false [doc native-loading-tides.md 1.1 table]. Showcase: the loader writes the row from `NativeReloadOnTide` (`main.lua:1651`), which is **false** (`config.lua:33`, comment "the map has no tide actor yet" is stale: a perimeter tide exists). A tide there therefore runs `ApplyTideReset` but no reload [inferred]. **Tide respawn of loot and enemies is untested** (worklog V4-087, G-02).
- **What the save remembers** (`USpawnerGameData`, inside `PRGameData.SpawnSaveData`) [sdk :5724-5745]: `npcSpawners` (SpawnerId -> map of live NPCs as `FNPCGameData`: `InstanceId`, `TypeID` tag, `Transform`, health, awareness, POI, command), `anomalySpawners`, `anomalies`, `SavedCorpseTypes`, `FurnitureLootData`, `LootSpawnerData` (`IsEmpty`, `IsSpawned`, items), `LootTableExludes`, `LootTablePoints`, `spawnSeed`, `PickedUpItems` (string ids), `SpecialGenerators`, `ExcludedGenerators`, `GeneratorsHP/Transforms/Cooldown`. API `RemoveNpcData(SpawnerId, InstanceId)` suggests killed NPCs are removed from the saved set and are not refilled until a reset [inferred]. Keys are actor-name based (`<Level>><Actor>` or `SpawnerInstanceID`), so only editor-placed, stably named actors persist [doc sdk-gameplay-bps.md 3]. How long a kill is remembered = until `ApplyTideReset` clears it [inferred; the native body is unread].
- **Rifts** = `BP_MonsterSpawnGenerator` (native `SpawnerGenerator`), visible shootable object with `HitPoints`, `generatorID` tag, `Spawners[]`, `CooldownSeconds`, `AlternativePlaces[]`; destroyed -> drops `Item.Artifact.Shard` (`ShardSpecial` if `Special()`) [doc enemies-loot.md 2.3]. They re-call their spawners every cooldown while alive (stock cooldowns 90/180/240 s; showcase `COOLDOWN` T1 150, T2 180, T3/T4 210, T5 240 s, `v4/tiers.py:19`). Cooldown, HP and transform persist in `GeneratorsCooldown/HP/Transforms`. So "rift spawn times" is a real system: `CooldownSeconds` per rift, plus the tide re-roll. Which generators are kept per level: `FLevelConfig.AllowedGenerators` (Min/Max); the showcase sets `NativeGenerators = 33` (the donor's 3 culled rifts to 3) [gotchas 2026-10-26]. `DA_GameConfig` also names `SpecialGeneratorsCounts`, `BannedFromBeingSpecial`.
- **Wild spawners** (`Wild` true) spawn on player proximity; `OnWildSpawnerCleared` fires when one is emptied [sdk :1258, doc enemies-loot.md 2.2 inferred].
- **Spawn guards.** `DA_SystemConfig.NPCSpawnMinDistanceFromPlayer` 2000 cm, `NPCMaxDistanceFromSpawner` 20000 cm, `NPCSpawnerRestoreRadius` 1500 cm [doc enemies-loot.md 2.2]. Nothing spawns within 20 m of the player.

## 4. Zone tiers and enemy scaling

- **Stock has no "tier" field.** Zones differ by content: Buffer (42 enemies, 4 types: Spider "Spawn", Fragment, Phantom, Mimic PM), Construct (87; + Seeker, Hunter, Commando), Factory (160; armoured everything), Kolhoz (149), Castle (64; SWAT, Marksman, Slider) [doc enemies-loot.md 1, density-2.7.2.md]. Armoured variants occur only in Castle, Factory, Kolhoz [doc enemies-loot.md notes]. Stock knobs that scale globally: `GameDifficultyConfig.EnemyCount` additive -1/0/+1, `EnemyHealth` x0.25-2, `EnemyDamage` x0.25-3, `EnemySense` x0.5-1.25 [doc]. No per-spawner tier or tide field.
- **Showcase tiers T1-T5 are generator concepts** [code]. `gen/maps/itrshowcase/brief.json` `tiers`: T1 = Pervomay/Buffer (42 enemies), T2 = Construct (87), T3 = Factory (160), T4 = Kolhoz (149, 25 % of stash rolls from the T5 pool), T5 = Castle (6.5/ha). Each of 12 pockets P1-P12 has one tier (P1 T1; P2,P3 T2; P4-P7 T3; P8-P10 T4; P11,P12 T5). `v4/tiers.py` (`TIER_OF`), `tools/population.py` `ARCH`/`THEME`/`SPAWN_PLAN` (archetypes per area with `Monsters` map, `AlternativeMonstersMax`, `Radius`, `CanWalkAway`, `SnipingMode`), `loot_tiers.py`, `missions_gen.py` (missions follow the pocket tier). All of it is baked into the level at build time: the `BP_MonsterSpawner.Monsters` TMap, `AlternativeMonstersMax` (int at 0x32C), loot-table tags per tier. The cooked level holds one fixed roster per spawner.
- **Tier-dependent loot**: loot manifest tags per tier and `LootArray` budgets are global per tag [doc loot-budgets.md, enemies-loot.md 3.3].
- **Minimum change to "downgrade a zone to T1".**
  - At load (build-time) [inferred from code structure]: change `TIER_OF[pocket]` (brief.json) and regenerate; one tier per pocket and a fresh build/cook per state. Possible only as a static variant, not as live state.
  - At runtime [inferred, unproven]: before a spawner fills, rewrite the `Monsters` TMap (`AMonsterSpawner.Monsters`, `AlternativeMonstersMax`) of the pocket's spawners to the T1 archetype, from Lua or a Blueprint. Already-saved NPCs are restored by `SpawnSavedNPC` from `npcSpawners` with their saved `TypeID`, so those would keep their old type until reset [inferred]. Nothing in the level changes loot tables per state at run time; the `LootArray` entries are global by tag [doc].
  - Cheaper lever: spawner count. Zero a spawner's `Monsters`, or leave a spawner's `SpawnerInstanceID` as "killed" in `npcSpawners` [inferred]. And rifts: remove their ids via `SpecialGenerators/ExcludedGenerators` [sdk] or destroy them.
  - Global difficulty multipliers are per save, not per area [sdk `PRGameData.GameDifficultyConfig`].

## 5. Keeping enemies out

- **How the Hub stays enemy-free**: it simply contains no monster spawner. A scan of all Hub umaps finds no `BP_MonsterSpawner_C`; spawners and generators exist only in `L_Zone_<Z>_Monsters` sublevels [data: pak scan; doc enemies-loot.md 2.1]. The Hub has its own `BP_RadiusOuter` fog plane and `ReloadOnTideHappening` false. There is no safe-zone concept as a class: none in the SDK (grep for SafeZone/NoSpawn/NavLink/AIBlock classes: no match) [sdk]. `BP_ShelterVolume` only affects the tide respawn. `BP_SpawnBlockingVolume` (box, default extent 1000) is used by the anomaly cluster system (referenced from `BP_AnomalyField`, cluster patterns, `DA_SystemConfig`); it blocks anomaly spawns, not NPCs [data names; effect inferred].
- **Navmesh.** One static navmesh baked in `L_Common`: `RecastNavMesh-Default` (agent radius 20, height 140, step 40, cell 20) and `-Big` (radius 400), 18 `NavMeshBoundsVolume`s; `RuntimeGeneration = DynamicModifiersOnly` so new geometry gets no runtime navmesh and a sublevel's baked tiles attach to `L_Common`'s [doc map-making.md 188-191, 261-268]. Showcase navmesh is baked in the editor and cooked; there is one `NavMeshBoundsVolume` per pocket [code `v4/placements.py:110`]. Hence a basement is excluded from AI movement simply by having no navmesh there (no bounds volume, or a `NavModifierVolume` with `NavArea_Null`). The showcase already uses `NavModifierVolume` area Null to exclude the lake (`v4/lakenav.py`, `build_showcase.py:1146`) [code]. NPC movement onto unbaked floor is not possible [inferred from Recast]. Also: "Editor-placed game prefab ... baked into the navmesh"; geometry spawned at run time is not [doc map-making.md 46, 136].
- **Chasing the player.** Mimics use `BT_Bot_Master` with Combat / Hide / Sniping trees plus EQS shoot positions; others use `Common/BT_NPC`. Perception: sight/hearing ranges per NPC (e.g. Fragment 60/40 m, SVD 120/100 m), `SenseNearRadius` 10 m, awareness decays, 60 s "lost" timer, then idle [doc enemy-ai-notes.md 2, 5; enemy-design-shoulds.md C1, G4]. Hearing goes through walls (no occlusion in vanilla) [doc enemy-design-shoulds.md B2]; telepathy channels (40 m broadcast, squad, death broadcast) alert groups without LOS [doc enemy-ai-notes.md 3]. Leash: `NPCMaxDistanceFromSpawner` 200 m. `CanWalkAway` false pins a squad to its spawner.
- **Doors and stairs.** Stock `Items/Furniture/BP_Door` is a VR-grippable physics door (`PhysicsConstraint`, `AngleLimit` 60, `DamageToBreak` 50, `Locked`, `CanBlockPlayer`); village houses have door frames, no leaves [doc interiors.md]. Whether NPCs open, push or break those doors, and whether they path down stairs: no data. Stock levels have indoor spawners (19 static NPC spawners inside house footprints) so NPCs do path through doorways onto interior navmesh [doc interiors.md]; multi-level buildings exist (Construct building with floors, `cover-data.md:76`). Stairs-following behaviour: unknown (look-list).
- **Other fences.** `NPCSpawnMinDistanceFromPlayer` 20 m prevents spawn on the player; keeping a spawner `Radius` away from the basement keeps spawning out. Hub-like absence of any spawner within `NPCSpawnerRestoreRadius` 15 m is the cheapest guarantee [inferred].

## 7. Persistence and UI surfaces

- Per-zone flags with no pre-made container: the nearest are `PassedTriggers` (tags must be registered or they never match: showcase uses registered unused `Mission.ID.Generic.*` / `Mission.Point.*` leaves, gotchas 2026-10-24) and `CustomMarkers` (free strings) [inferred as candidate carriers; unproven]. `LevelDecorItems` is keyed by level tag. - Saving in the showcase: `NativeSaves = true` (`config.lua:29`): the map saves like a zone; a save made inside the map continues there. With the mod removed, Continue would fail on an unknown tag unless the loader's guard rewrites it [doc native-loading-tides.md 1.2a].
- Level saves are triggered by level-row flags `SaveOnExit`, `Autosave` (60 s `AutosavePeriod` in `BP_PRGameMode`), `SaveOnLoad` [data/sdk]; the Hub row has Autosave off, zones on.

**UI surfaces** [doc ingame-map.md]:

- A zone-clearance display would need a new widget; stock gives no extension point besides the above [inferred].

## 9. Design references (web, about one page)

Only mechanics that bear on this feature.

- **State of Decay 2 outposts**: claiming needs cleared surroundings, enough influence and a free outpost slot; an outpost gives a perimeter safe zone, a supply locker, character swap; plague-heart territory must be destroyed before nearby sites can be claimed (a region gate). Sources: https://primagames.com/tips/state-decay-2-how-claim-outpost ; https://support.stateofdecay.com/hc/en-us/articles/4403310472973-Update-25-Homecoming ; https://almarsguides.com/computer/games/stateofdecay2/walkthrough/
- **Far Cry outposts (3, 4, New Dawn)**: liberating (clearing all guards) unlocks a fast-travel point; unalerted liberation pays more; enemies may counterattack a held outpost with a warning (FC4); New Dawn lets you reset an outpost at a higher difficulty for more reward. Sources: https://guides4gamers.com/far-cry-new-dawn/poi/outposts/ ; https://gamerguides.com/far-cry-3/guide/introduction/gameplay/outposts ; https://primagames.com/eguides/far-cry-4-eguide/enemy-bases/outposts
- **S.T.A.L.K.E.R.**: vanilla Call of Pripyat has fixed faction bases with truce rules (trespass makes a faction hostile); it has no capture system. Territory capture with held bases that spawn traders and medics comes from the Call of Chernobyl mod ("Warfare"): capture surroundings first, then the base; held bases let you hire squads. Sources: https://stalker.fandom.com/wiki/Duty_base ; https://www.moddb.com/addons/coc-extended-offline-eoc-for-1422-by-stason174-v603-v30
- **Escape from Tarkov hideout**: a persistent base built up with materials, giving crafting and faster healing; the stash is outside the raid so what you bring home survives. Source: https://www.shacknews.com/article/141320/tarkov-hideout
- **DayZ**: no built-in safe zone; bases are player-built and physically exposed (my search found little on raids). Source: https://www.inverse.com/article/10181-escape-from-tarkov-might-be-the-next-dayz
- Cross-cut: (a) safe place = storage + character swap + rest (SoD2); (b) region cleared -> persistent benefit + a counter-threat (FC4 counterattack, SoD2 plague heart); (c) clearing is gated by a visible boss-like object (SoD2 plague heart; ITR analogue is the rift) ; (d) fast travel to held points (FC3). Fandom pages were unreachable (HTTP 402), so details come from search summaries.
