Loot

How Into the Radius decides what's in a stash, how to set that up in your map, and how to get items from other mods into it. Open the example project next to this page and compare as you go.

Have these open
  • The map in the editor: project/Content/Mods/ItrShowcase/L_ItrShowcase.umap. READMEBORING says what opening it needs.
  • The manifest: ItrShowcase.loot.json.
  • The example pak installed, if you want to see the result in game.

How ITR does loot

Loot starts at a loot node: an actor in the level that marks where items can appear. A node doesn't list any items. It holds a loot tag (a gameplay tag, which is a dotted name like Loot.Factory.Stash.Grey), a number of points and an id.

The game keeps one global list, LootArray, in its config asset DA_GameConfig. Each entry maps a loot tag to a loot table (a DataTable where each row is an item and its cost in points) and a budget (how many points all the nodes on that tag can spend between them).

When a level is prepared, each node does this once:

  1. It looks up its id in the save. If it already rolled, it keeps what it got.
  2. It asks for loot with its tag and points. The game spends up to the node's points, or whatever is left of the budget, on rows from the table.
  3. The result goes in the save under the node's id. A node that gets nothing hides itself.
  4. Once you're within 100 m, the items spawn and get packed into the node's box. Items that don't fit are dropped if the node has Exclude Non Fit on.

Used points are counted per table name, and they're kept in the save. A tag stops giving loot when its budget is spent. Stock budgets are small: Buffer's train station ammo tag has a budget of 32 against 140 points of placed nodes, so a lot of nodes come up empty. That's why a big map reusing stock tags turns out sparse, and it would eat the budget of the real zone as well.

A tide refills the nodes. I've seen that in this map, including from a tide that passed while I was in the Hub.

The picking is native code, so I've only seen it from the outside. A row repeated N times seems to count N times, which is how stock tables weight items. I got that from the data. I haven't read the pick itself.

Add loot to your map

Plan first: pick option A, B or C

OptionYou makeItems from other modsBudget
A: borrow a stock tableA line in the manifestShould arrive, since you roll the same table a stock zone does. Not tested.Your tag's number, but used points are shared with that stock zone.
B: your tableA DataTable and a line in the manifestNoSeparate
C: your table plus slots (this map)Everything in B, plus a composite table and empty stand-insYes, see custom itemsSeparate

Also decide how many tags. One per kind of node per difficulty tier is what this map does, for example ammo, food and two stash colours for each tier. For the budget, add up the Loot Points of the nodes on a tag if you want every node to fill. A lower number makes the tag scarce the way stock zones are.

In one test a budget of 1 hid the node and a budget of 0 didn't block anything, so don't use 0 to switch a tag off.

Option A: borrow a stock table

  1. Make Config/Tags/MyMapGameplayTags.ini in your project with the section line [/Script/GameplayTags.GameplayTagsList].
  2. Add a line for your tag: GameplayTagList=(Tag="Loot.MyMap.T1.Ammo",DevComment="")
  3. Restart the editor, so it picks up the tag.
  4. Drag BP_RandomLoot from /Game/ITR/BPs/Items/Containers into the level.
  5. Set Loot Table to your tag and Loot Points to 4.
  6. Set Instance Id to something nobody else will use, such as MyMap-R1-RandomLoot-000001, and Instance Id Prefix to MyMap-R1-RandomLoot-. Stock nodes have ids like RandomLoot-3880, so a longer id with your map's name won't clash. I don't know what the prefix does by itself.
  7. Copy Example.loot.example.json from the itr-common loader to your loader's Scripts folder as MyMap.loot.json, where MyMap is the map's Name in config.lua.
  8. Keep one entry and fill in tag, source_tag (the stock tag to borrow) and loot_points.
  9. Cook and install the map with build-map.ps1, and start the game.
  10. Open UE4SS.log and find loot manifest registered. It should say 0 without donor, 0 failed.
  11. Go to the node in game.

The loader skips a tag whose source_tag isn't in LootArray, so check the spelling. The stock tags are in Config/Tags/LootGameplayTags.ini, which comes with the SDK's Config.

Option B: your table

Do the steps for option A first, then:

  1. In the Content Browser, go to /Game/Mods/MyMap/Loot. Right-click, Miscellaneous, Data Table, and pick the row structure PRLootEntryConfig. Name it DT_Loot_MyMap_T1_Ammo.
  2. Add rows, one per item. Give the row names a prefix of your choosing (MyMap_0, MyMap_1). Repeat a row to make that item more common.
  3. In the manifest, add table_name (DT_Loot_MyMap_T1_Ammo) and table_asset (/Game/Mods/MyMap/Loot/DT_Loot_MyMap_T1_Ammo.DT_Loot_MyMap_T1_Ammo). Keep source_tag: the loader needs it to find the stock tag to borrow, and uses that stock table if it can't load yours.
  4. Cook, install and start the game. In UE4SS.log, find loot manifest registered. The number before custom tables should equal the number of manifest entries that name a table.

The cook packs only /Game/Mods/MyMap, so your table has to be in that folder. This page describes main.lua in this map's loader. I haven't checked the itr-common loader against it.

Make it work with custom items

How a row reaches an item

A loot row holds a gameplay tag and nothing else about the item. At roll time the game looks that tag up in the item table. So a modded item needs two things to drop: a row somewhere in the loot table being rolled, and a row in the item table. Neither of those depends on the level.

How a mod's item gets into a stock table

A loader can't add rows at runtime, because Lua can't reach a table's row map. Item mods get around that with Common Mod Dependencies, the shared framework they plug into, and an Unreal feature called a composite table. A composite has no rows to edit. It has a list of parent tables, and when it loads, the engine builds its rows by adding each parent's rows in order. A later row with the same name replaces an earlier one, and a parent that doesn't exist is skipped.

Common Mod Dependencies does this:

  1. It replaces DA_GameConfig, so all the stock loot tags point at composites such as /Game/Mods/LootTables/Vanilla/DTC_Loot_Factory_StashGrey.
  2. Each composite has 12 parents: the stock table first, then 11 slots, /Game/Mods/ModdedData/User0 to User10.
  3. It installs every slot as an empty table.
  4. It does the same for items: DA_InfosConfig points at composites like DTC_ItemInfosVanillaScav, with slots User1 to User10.

A mod adds an item by putting a table with rows at a slot path, in a pak that wins over the empty one. A pak whose path sorts later wins the same file, so ~mods beats Paks, and zzz_ beats AA_. Here's a slot path, for the stock Factory grey stash table, slot 5:

/Game/Mods/ModdedData/User5/LootTables/Vanilla/DT_Loot_Factory_StashGrey_V_User5

The framework comes in three versions, and each points the tags at one of three sets of tables: Vanilla (_V_), Scavenger (_SC_) and Stalker (_ST_). The item mods I've looked at fill all three.

The three item mods I've got installed use slots 0, 5 and 6. Two mods in the same slot overwrite each other, and I don't know of a list of who uses which.

What that means for your map

A plain table you make doesn't list the slot tables, so a mod's rows never get into it. To fix that, make your table a composite too, with the same slots as parents. Then a mod's rows land in the stock zone and in your map, and the mod needs no change.

Option C: one table, one set

Do the steps for option B first. The table you made there is your base table. In these steps it's a tier-3 grey stash modelled on the stock Factory one.

  1. Pick the stock table you modelled yours on: DT_Loot_Factory_StashGrey. Copy the name exactly. Some have odd spellings, such as DT_Loot_Buffer_CarDEpot_Ammo.
  2. Give your table's rows a prefix if they don't have one. A stock-style NewRow_0 could get replaced by a mod's row of the same name.
  3. Create the folder /Game/Mods/ModdedData/User0/LootTables/Vanilla.
  4. In it, make a Data Table with the row structure PRLootEntryConfig, named DT_Loot_Factory_StashGrey_V_User0. Add no rows. It's a stand-in: the editor needs something at that path to save a reference to it.
  5. Do the same for User1 to User10, changing the number in the folder and in the name. That's 11 per table, and an editor Python script would save you some clicking. There isn't one in this repo.
  6. In /Game/Mods/MyMap/Loot, right-click, Miscellaneous, Composite Data Table, with the same row structure. Name it DTC_Loot_MyMap_T3_Stash_Grey_V.
  7. Open it. In the Properties panel, add 12 entries to Parent Tables: your base table first, then the stand-ins from 0 to 10. Save.
  8. In the manifest, set table_name and table_asset to the composite.
  9. Cook. Check the pak with UnrealPak <pak> -List: there should be no ModdedData line. build-map.ps1 only packs /Game/Mods/MyMap, so they stay out. An empty stand-in in your pak could beat a mod's real slot table.

Without Common Mod Dependencies the slots don't exist, so the engine skips them and you get your base rows. That's from the engine source. I haven't tested it in game.

All three sets

With one set, people on the Scavenger or Stalker version get the Vanilla rows. To follow the version they're on, make three composites for each table (_V, _SC, _ST), with slots in LootTables/Vanilla, LootTables/Scavenger and LootTables/Stalker, and list all three in the manifest under table_variants. The loader in this repo picks the set once at startup, from the folder the stock tag's table is in. The itr-common loader reads table_name only, so use main.lua from this map's loader for this. I've only run the Vanilla set.

Keeping the mod's share right

A mod's rows compete with yours by row count, and I assume mod authors balance against the size of the stock table. If your base table is much shorter than the stock one, mod items come up more than they would in a stock zone. To even that out, repeat all your rows max(1, round(stock rows / your rows)) times. Mod rows don't add to your budget. They share it.

What reaches a composite map and what doesn't

A mod that...Reaches your map?
fills a slot of a stock table your composite listsYes. I've seen it in this map.
fills a slot of a stock table you didn't listNo. Each composite takes the slots of one stock table, so tier 3 ammo here gets the Quarry ammo slots and misses the other Factory areas.
replaces the stock tables at their stock paths (a loot overhaul)No. The stock table isn't a parent of your composite.
places fixed items through the framework's level configNo. That data has one field per stock level.
replaces the stash or node BlueprintsShould do, if you place the stock classes. Not tested.
changes the stock budgetsWith LootFollowBudgets on, your budget scales by the same ratio, clamped 0.25 to 4.

Your map's items

This map adds no new items, so none of it is tested here. It's the route a small item mod takes, and I'd build it as a separate pak the way they do, since build-map.ps1 only packs /Game/Mods/MyMap. Making the item itself (Blueprint, hand poses and so on) isn't covered on this page.

  1. Add a line for the item's tag to a tag ini in Config/Tags. Pack that ini into a small tag pak with the mount point ../../../IntoTheRadius/Config/Tags/ and a file name nobody else uses. build-tags.ps1 does this for a level tag. An item tag has to be registered in game, or a saved item loads as nothing.
  2. Add the item's row to a free slot's item tables, in the item's pak: DT_ItemInfos_User<n>_VanillaScav, DT_ItemInfos_User<n>_ScavNoshop and DT_ItemInfos_Stalker_User<n>, in /Game/Mods/ModdedData/User<n>.
  3. Add a row with that tag to your map's base table. Or add it to the loot slot tables of that same slot number, in the item's pak, and it reaches stock zones as well as your composites.

You can also put another mod's tag straight into your base table. The editor needs that tag in an ini too. I haven't tested what happens when that mod isn't installed.

Without Common Mod Dependencies I don't know a clean way to add an item. You'd have to replace DT_ItemInfos, and only one pak can win that file.

Budgets and saves

The used points in a save are stored under the composite names, so the rolls come from the map's tables and the stock tables' budgets aren't touched. In the earlier build, with 68 tags, tags with plain tables (artifacts and signature stashes) ran out of budget before every node had rolled, so budgets did limit loot. Every tag's budget is now at least the points of the nodes on it. To get scarcity, lower a budget in the manifest.

After the loader change I entered the map, went through three tides, left and came back, and used Continue. The saves had used points only under this map's table names, all the artifact nodes had rolled, and the 9 signature stashes were full. I haven't repeated that with the latest loot build.

I've seen modded items in the map's stashes in VR, and a read of an earlier save showed modded magazines and consumables, including Item.Weapon.Ammo.45ACP.FMJ, a tag that isn't in the game's stock tag lists. What turns up depends on what each mod fills. One of the item mods I have installed has no Vanilla rows for Buffer's tables, so by itself it adds nothing to T1.

Checklist

  • Your loot tags are in a Config/Tags ini, and the editor shows them in the Loot Table picker.
  • Every node has a tag, points and an id no other node has.
  • The manifest is in the loader's Scripts folder and named after the map's Name.
  • UE4SS.log says 0 without donor, 0 failed.
  • If you made tables: every table_asset in the manifest is a path in your pak, and the log's custom tables count equals the number of entries that name a table.
  • With slots: UnrealPak -List on your pak shows no ModdedData line.
  • With slots: your composites list your table first, then slots 0 to 10 of one stock table.
  • In game, items appear when you get near a node. After a change, you tested with new ids or a new save.
  • With an item mod installed, its items turn up in a node on a tag whose stock table that mod fills.
  • Save, quit, Continue: what you left in the node is still there, and picked-up modded items are still modded items.
